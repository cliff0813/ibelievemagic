# Google Sheets 課程報名系統設計

日期：2026-10-31

狀態：設計已核准，尚未實作

## 目標與範圍

以 Google 試算表維護 GAS 報名頁使用的課程資料及報名資料，提供公開報名、查詢與取消申請，以及受保護的管理操作。既有 GitHub Pages／Next.js 課程目錄仍以專案內 `data/courses.json` 顯示；課程詳情頁新增前往 GAS 報名頁的連結，並傳入課程 ID。

第一版包含個人報名、團體報名、名單查詢、整筆取消申請、管理員取消審核、課程報名開關，以及課程資料為空時的 JSON 備援。不包含線上金流、價格計算、名額上限／額滿自動停止、課程內容管理介面。課程資料直接在試算表維護；管理介面只負責報名檢視、取消審核及報名開關。由於不實作名額計數，管理員須在額滿時手動關閉報名。

## 架構

- **現有網站：** Next.js 靜態網站繼續由 `data/courses.json` 提供目錄和詳情；報名連結開啟公開 GAS 部署，附上 `courseId` 供預選課程。
- **公開報名部署：** GAS HTML Service 提供報名、查詢與取消申請頁，以試算表資料服務，不向瀏覽器公開試算表憑證。此部署以擁有者權限執行並允許公開存取。
- **管理部署：** 使用同一 GAS 專案的獨立部署，要求管理員以 Google 帳號登入，並以登入者身分執行。每次管理操作都在伺服器端核對 Gmail 白名單；無法取得登入 Email 時拒絕存取。每位管理員必須有試算表權限並完成授權。
- **版本管理與備援：** GAS 原始碼放在 repo 的 `gas/` 目錄並納入版本控制。部署時從 `data/courses.json` 產生／同步 GAS 使用的 JSON 備援快照，避免手動維護兩份資料。若課程表沒有可用課程列，GAS 使用此快照；若試算表讀取失敗，頁面明確顯示錯誤，不以備援資料掩蓋服務故障。
- **圖片：** 既有 Supabase Storage 公開圖片 URL 繼續使用；新圖片可放在專案 `public/images/courses/`，由 GitHub Pages 提供公開 URL。課程表只存圖片 URL，GAS 頁面以 URL 載入圖片。

## 試算表資料表

1. **Courses：** 每門課一列、一個固定開課日期。包含穩定課程 ID、標題、日期、起訖時間、地點、上課方式、圖片 URL，以及報名開關。GAS 報名頁只呈現日期未過、報名仍開放的課程。
2. **Bookings：** 每次送出一列，包含報名編號、不可預測的查詢代碼、課程 ID、團主聯絡姓名／手機／Email、報名狀態及建立時間。
3. **Participants：** 每位學員一列，連結至 Booking，包含姓名、手機、Email、LINE 名稱。團報至少三位學員；個人報名仍可一位。
4. **CancellationRequests：** 每筆申請一列，包含申請 ID、Booking ID、原因、審核狀態、管理員及處理時間。
5. **AuditLog：** 記錄管理員開關報名、核准／拒絕取消等操作及時間，不記錄多餘個資。

課程報名開關支援自動、手動開放及手動關閉。以台灣時區計算，課程日期前兩天的 00:00 起自動截止；手動關閉可提早停止報名。手動開放不能越過自動截止時間重新開放。

## 報名、查詢與取消流程

### 報名

- 公開頁採單頁表單：選擇可報名課程、填寫團主聯絡資料，再填每位學員資料；團報可新增／移除學員，最低三位。
- 沿用現有須知要求的學員姓名、手機、Email、LINE 名稱，並要求同意個資使用說明。
- 第一版只收報名資料，不計算價格、不收款，也不提供名額計數。
- 送出前由 GAS 在 `LockService` 保護下再次確認課程開放狀態並檢查重複，再寫入報名。比對同課程／日期的既有有效報名；手機去除格式符號、Email 去除首尾空白並忽略大小寫。手機或 Email 任一相同即視為已有報名。不同團員在同一筆團報內可共用聯絡資料，但完全相同的團員資料不可重複列入。
- Booking 狀態為 `SUBMITTED` 或 `CANCELLATION_PENDING` 時，均視為有效報名；核准取消後改為 `CANCELLED`，才不再參與重複檢查。
- 成功頁顯示可複製的報名編號並寄到團主 Email。若寄信失敗，已寫入的報名不撤回，頁面明確顯示寄信失敗並保留報名編號，避免學員因重送而重複報名。

### 查詢與取消

- 團主使用「報名編號 + 團主手機」查詢；系統只回傳相符的整筆團報，不提供公開搜尋或其他學員資料。
- 團報以整筆為取消單位，只有團主的手機及報名編號可提出申請。
- 取消申請需由管理員核准或拒絕；申請待審期間報名仍有效。核准後整筆 Booking 改為 `CANCELLED`，保留原始報名及審核紀錄。系統不自動處理退款。
- 申請結果通知團主 Email；通知失敗需明確記錄並提供管理員可見的處理狀態。

## 管理與隱私

管理介面可檢視報名、核准／拒絕取消、開啟／關閉報名；課程文字與日期直接在 Courses 表維護。管理 API 每次都要進行登入身分與 Gmail 白名單檢查，不能只在前端隱藏管理按鈕。白名單與部署設定不提交為公開憑證。

試算表只分享給必要管理員。伺服器端驗證及跳脫使用者輸入；執行紀錄不得寫入姓名、電話、Email、LINE 名稱、報名編號或查詢代碼。第一版不自動刪除報名或稽核紀錄，管理員依業務保存政策處理。

## 錯誤處理與驗收

- 試算表讀取失敗、資料格式錯誤、重複報名、截止／關閉課程及驗證失敗都要明確回報，不接受不完整或失敗的報名。
- JSON 備援只用於課程表沒有可用課程列；試算表服務錯誤不得默默切換。
- 驗收至少涵蓋：課程表空白與讀取失敗的不同結果、JSON 備援課程日期與自動截止、手動開關優先規則、截止後不可重新開放、團報最低人數、同課程／日期手機或 Email 重複檢查、團報共用聯絡資料、同時送出防重、報名編號與團主手機驗證、整筆取消審核狀態、管理 Gmail 白名單及無法取得登入 Email 時拒絕管理操作、寄信失敗仍能取得報名編號。
