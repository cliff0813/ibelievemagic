# 管理頁新增、編輯與刪除課程設計

日期：2026-11-01

狀態：設計已核准，等待規格審閱；尚未實作

## 目標與範圍

在既有 GAS 管理頁提供課程新增、編輯及刪除功能。課程資料仍以 Google 試算表的 `Courses`、`CourseOutline`、`CoursePricing` 為來源；網站公開端點已即時讀取這些分頁，因此管理頁儲存後，網站訪客重新載入即可看到變更，不需重新部署 GitHub Pages。

此功能限既有管理部署與管理員白名單使用。為發布新的管理操作，需更新並發布一次 GAS 管理程式；此後新增、修改與刪除課程只寫入試算表，不需再部署網站或 GAS。

報名資料不可因課程刪除而失去關聯。課程 ID 建立後不可修改。刪除與修改資料需保留既有報名列及其他報名資訊。

## 管理頁互動

- 新增表單固定顯示在管理頁前段，現有報名開關、取消審核及報名紀錄區塊保留。
- 課程清單每個課程提供「編輯」與「刪除」操作。
- 新增與編輯共用同一表單。編輯會把所選課程及其課綱、費用載入表單，並鎖定 `courseId`；提供取消編輯操作。
- 刪除前顯示二次確認。刪除遭拒或寫入失敗時，保留明確錯誤，不呈現成功狀態。
- 成功或失敗回應顯示於管理頁狀態區；不使用使用者資料作為 HTML。

## 欄位與資料操作

### Courses

欄位採 `SHEET_SCHEMAS_.Courses` 定義：

`courseId`、`title`、`date`、`startTime`、`endTime`、`location`、`mode`、`image`、`manualRegistrationMode`、`description`、`instructor`、`instructorBio`。

- 新增時自動產生 UUID，ID 欄位允許提交前編輯；後端驗證不為空且唯一。
- 編輯時 `courseId` 不可修改。
- 新增必填：`courseId`、`title`、`date`、`startTime`、`endTime`。其他課程欄位可留白。
- 日期採 `YYYY-MM-DD`、時間採 `HH:mm`。新增課程的 `manualRegistrationMode` 固定為 `AUTO`；編輯其他欄位時保留課程現有報名模式，不覆蓋管理頁既有的報名開關設定。

### CourseOutline 與 CoursePricing

- 課綱每列為 `courseId`、`sortOrder`、`item`；費用每列為 `courseId`、`sortOrder`、`label`、`price`。
- 表單允許新增或移除多列。儲存時依畫面順序從 1 產生 `sortOrder`；兩者都可不填任何列。
- 費用需為數字；課綱項目、費用標籤及金額由後端再次驗證。
- 編輯課程時，以表單送出的課綱與費用完整取代該課程原有的關聯列，並保留其他課程的列。

## 關聯、時程與刪除保護

- 每個伺服器端管理方法重新呼叫 `requireAdmin_()`；不得將 GAS 管理操作暴露到公開唯讀課程端點。
- 所有課程變更以 GAS Script Lock 保護，避免並行管理操作互相覆蓋。
- 若修改課程日期，將同一 `courseId` 的所有 `Bookings.courseDate` 同步更新，包括已取消等歷史狀態；報名列其他欄位不變。時間欄位不在 Bookings 中，不改動報名列。
- 刪除時先檢查 `Bookings` 中是否有任何該 `courseId` 的列，不論報名狀態。若存在即拒絕刪除並說明原因。
- 無報名紀錄時，刪除該課程及其 `CourseOutline`、`CoursePricing` 所有關聯列；不提供刪除報名紀錄或操作紀錄的能力。

## 錯誤處理與資料完整性

- 前端驗證提供即時回饋；GAS 後端必須獨立驗證必填欄位、日期／時間格式、課程 ID 唯一性、費用數字及操作目標存在。
- 多分頁操作在寫入前完成所有可行的驗證。所有錯誤都明確回傳至管理頁；部分寫入不得回報成功，且要說明操作、受影響的課程 ID 與恢復方式。失敗時保留表單中的原始輸入，讓管理員能以相同資料重試。
- 操作須能安全重試，避免重複新增課程、課綱、費用或報名日期更新。新增若遇到同 ID：若既有課程列與本次課程資料相同，視為同一新增操作的重試並補齊關聯列；若資料不同則拒絕重複 ID。編輯以該課程 ID 冪等地更新欄位、取代其關聯列並同步報名日期。刪除先移除關聯列、最後移除課程列；重試可清理尚存的關聯列，目標及關聯列都已不存在時視為刪除完成。
- 對重複 ID、目標課程不存在、已有報名禁止刪除、權限拒絕及試算表寫入失敗提供可辨識的錯誤。

## 測試與驗收

- GAS 服務測試：新增課程與課綱／費用正確關聯及排序；預設報名模式為 `AUTO`；重複 ID、格式錯誤、非數值費用、未授權呼叫及不存在的修改目標會明確失敗。
- GAS 編輯測試：更新課程欄位與關聯列；不更改 ID；保留既有 `manualRegistrationMode`；替換關聯列時不影響其他課程資料。
- 時程測試：修改日期更新同課程所有狀態的報名 `courseDate`，且不更動其他報名欄位；失敗不回報成功，可恢復。
- 刪除測試：存在任一報名列時拒絕刪除；沒有報名列時刪除課程、課綱與費用，其他課程及報名紀錄均保留。
- 管理頁測試：固定新增表單、UUID 編輯、編輯載入及取消、動態課綱／費用列、刪除確認、成功與錯誤訊息皆符合設計。
- 回歸測試：既有報名管理、取消審核、報名開關與公開課程資料流程維持有效；執行 GAS 測試與 Next.js 靜態建置。
- 雲端驗收需由管理員部署新版 GAS 管理程式，登入實際管理網址操作，並確認公開網站重新載入後讀到最新試算表資料。部署與帳號驗證不由本機測試代替。
